# 双 PDF 核心接入

本目录移植的是 `../pp/paper-parallel` 在本机修正后的核心，并非远端旧版。来源仓库基线为 `xing666173/paper-parallel` 的 `b14de03878194ed385c2aa1ae9e016dae73f606a`，包含其后本机完成的 V4.1 模型名、公式保护、渲染恢复及可读优先策略修正。

## 接入范围

实际网页入口为 `index.html → browser/main.js`。原来的侧栏、论文库、检索、引用网络、阅读助手和笔记界面继续沿用。未修改历史 React 版 `src/`。

- `adapter.js` 负责调用 Paper Parallel 的解析、视觉版式识别、翻译、Typst 编译、语义对齐及逐页检查。
- `runtime.js` 的 `/translate` 与 `/compose` 共用此核心。阅读页、论文操作菜单、任务恢复、译文校对重排入口共用翻译设置弹窗。
- 原文 PDF 与原文笔记坐标继续使用 IC 原有数据；新核心只写中文 PDF、译文文字层、对齐映射及成品报告。
- `alignment.js` 将零起始页码转换成阅读器页码，保留同一语义单元的不连续矩形。中英文按内容定位，可以有不同页数。
- 新核心缓存单独保存在 `icrf-paper-parallel-v1`。旧 IC 译文缓存不会混入。清空操作只作用于当前论文的新核心缓存；删除论文同时删除其新核心缓存。
- 校对页读取新核心的真实译文记录。保存时校验数字和公式标记；再次排版使用匹配缓存，仍需确认本轮模型调用。

## 依赖和构建

移植核心位于 `engine/core`，类型位于 `engine/types`。它使用独立的 `paper-parallel-pdfjs` 别名（PDF.js 4.10.38）；原网页的 PDF.js 6 不变，避免 Worker 版本冲突。Typst WASM、中文字体和许可证由 `scripts/copy-pdf-assets.mjs` 在开发与构建前复制到本地静态目录，无需在测试中访问字体 CDN。

根目录双击 `启动本地测试.cmd`，地址为 `http://127.0.0.1:5174`。关闭终端或按 Ctrl+C 可停止。依赖采用锁文件安装，端口占用时直接报错，不静默切换到另一个地址。

## 从头验收

1. 打开本地网站，在设置页配置真实 DeepSeek 接口和 Key；模型使用 `deepseek-flash`。
2. 导入 cuZK 原文，进入双 PDF 对照，点击整篇翻译。
3. 勾选“清空本篇双 PDF 缓存，从头运行”，选择“优先生成可读版本”，确认正文和页面图片发送范围后开始。
4. 等待生成结果和逐页检查完成。检查英文与中文各自页数，双向点击对应、同步和独立滚动、逐页渲染、下载、校对缓存以及刷新恢复。
5. 从中文面板下载检查报告。报告取自该份已保存 PDF 的输出记录，不能拿上一次失败任务的日志作为本次报告。

`readable-first` 可交付带待复核问题的 PDF；报告仍保持 `pass: false` 和 `deliveryStatus: needs-review`。它不表示严格审校通过。解析失败、正文翻译保护校验失败、编译失败仍会阻止交付。

## 当前边界

- 此版核心只生成简体中文单栏 PDF，视觉步骤使用 V4.1 Flash。加密 PDF 需先解密再导入。
- IC 原有版式检查面板保留用于原文阅读信息；新 PDF 的版式由新核心重新识别，不使用旧引擎的人工分块作为排版输入。
- IC 原有项目 ZIP 格式仍可导出原文、中文 PDF、笔记和现有对齐字段，但未包含新核心的全部中间缓存与编辑记录；不要用旧 ZIP 当作新核心缓存的无损备份。跨浏览器迁移后需从原文重新生成双 PDF。
- 本机运行证据保存在忽略提交的 `outputs/parallel-*`，其中浏览器配置目录含本地设置，不应上传。仓库、作业记录与检查报告不写 API Key。
