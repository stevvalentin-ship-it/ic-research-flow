# 芯研流（IC Research Flow）设计规格

## 1. 产品目标

构建一个部署在 GitHub Pages 的纯前端科研工作台。每位访问者在浏览器内配置自己的 DeepSeek 兼容接口、批量导入本地集成电路论文 PDF，并完成论文解析、集成电路知识分类、本地检索、影响力排序及类思维导图展示。

网站不建立共享账户或云端论文库。每位访问者拥有独立的浏览器本地数据库，论文文件不会上传到 GitHub 或本站服务器。

## 2. 首版范围

### 包含

- DeepSeek/OpenAI 兼容接口地址、模型和 API Key 配置与连接测试。
- 批量拖拽或选择 PDF；单批最多 50 篇，总库建议不超过 500 篇。
- PDF 文本、元数据和参考文献的浏览器端解析。
- 可恢复的处理队列：等待、解析、AI 分析、索引、完成、失败。
- 集成电路受控知识体系、多标签分类、置信度与页码证据。
- 浏览器本地中英文全文检索，单次最多召回 50 篇。
- DeepSeek 查询扩展与候选论文重排。
- 时间感知、主题个性化、引用语义加权的 IC-Influence Rank。
- 内容知识树、影响力网络和 12–15 篇核心论文清单。
- GitHub Pages 静态部署和哈希路由。

### 不包含

- 用户注册、共享论文库或团队协作。
- 受版权保护论文的联网下载。
- 服务端数据库、服务端 OCR 或后台任务。
- 对扫描版无文本 PDF 的 OCR；此类文件显示明确提示。
- 引用指标的付费数据源。

## 3. 技术架构

### 3.1 运行形态

- React + TypeScript + Vite 单页应用。
- GitHub Pages 托管静态 HTML、CSS 和 JavaScript。
- HashRouter 保证项目子路径刷新不产生 404。
- PDF.js Web Worker 解析 PDF，避免阻塞主线程。
- Dexie/IndexedDB 保存 PDF Blob、文本分块、分析结果、任务与设置。
- MiniSearch 建立本地 BM25 风格全文索引；使用 `Intl.Segmenter` 与集成电路术语词典处理中英文。
- D3 force/SVG 绘制可缩放、可拖拽的知识树和引用影响力图。

### 3.2 数据流

`用户选择 PDF → 计算 SHA-256 去重 → IndexedDB 保存 → PDF.js 提取文本/页码 → DeepSeek 返回结构化分析 → 建立本地全文索引与引用边 → 用户检索 → 召回最多 50 篇 → DeepSeek 重排 + IC-Influence Rank → 多样性筛选 12–15 篇 → 图谱与证据面板`

只有发送给用户所配置 DeepSeek 接口的分析文本会离开浏览器。PDF 原文件不发送到本站或 GitHub。

## 4. 本地数据模型

### Paper

- `id`: SHA-256 文件指纹。
- `fileName`, `fileSize`, `blob`, `pageCount`, `createdAt`, `updatedAt`。
- `title`, `authors`, `year`, `doi`, `venue`, `abstract`。
- `fullText`, `pageTexts[]`, `analysisStatus`, `analysisVersion`。

### PaperAnalysis

- `paperId`。
- `domains[]`: 一级知识域、置信度和证据页码。
- `facets`: 研究对象、问题、方法、工艺节点、关键指标、应用场景、结论、局限。
- `keywordsZh[]`, `keywordsEn[]`。
- `references[]`: 标题、作者、年份、DOI、引用语义和证据页码。
- `summary`, `evidence[]`, `analyzedAt`。

### ProcessingJob

- `id`, `paperId`, `stage`, `progress`, `attempts`, `errorCode`, `errorMessage`, `updatedAt`。
- 阶段为 `queued | parsing | analyzing | indexing | completed | failed | paused`。

### AppSettings

- `baseUrl`, `model`, `analysisMode`。
- API Key 默认位于 `sessionStorage`；只有用户主动选择“在本机保存”时才写入本站域名下的 `localStorage`，并显示风险提示。

## 5. DeepSeek 适配器

- 使用 OpenAI 兼容的 `/chat/completions` 请求格式。
- 支持自定义 `baseUrl` 和模型名，官方默认地址为 `https://api.deepseek.com`。
- 连接测试发送最小请求，不记录密钥或响应正文。
- AI 输出要求放入 JSON 代码块或直接返回 JSON；解析器容忍代码围栏和前后解释文字。
- 每篇论文使用代表性文本包：标题/摘要区域、章节标题、方法与实验段落、结论、参考文献。单次请求不盲目发送整篇全文。
- 结构校验失败时自动追加一次修复请求；网络错误使用指数退避，最多重试两次。
- 队列默认串行分析，用户可暂停、继续或单篇重试。

## 6. 集成电路知识分类

一级知识域固定为：

1. 半导体器件与制造工艺。
2. 模拟、射频与混合信号电路。
3. 数字电路、处理器与 SoC 架构。
4. 存储器与存算一体。
5. EDA、验证与设计方法。
6. 电源管理与功率集成电路。
7. 测试、可靠性与硬件安全。
8. Chiplet、先进封装与三维集成。
9. 光子、神经形态等新型集成技术。

一篇论文可以进入多个知识域。每个标签必须携带 `confidence`、`evidencePage` 和简短理由；不满足 0.55 置信度的标签不进入主知识树。

## 7. 本地检索与筛选

1. 用户输入自然语言研究问题。
2. DeepSeek 将问题扩展为中文术语、英文术语、缩写和排除词；接口不可用时直接使用原查询。
3. MiniSearch 从标题、摘要、关键词、方法、结论和全文分块中召回最多 50 篇。
4. 候选论文按内容相关度生成紧凑证据包，分批交给 DeepSeek 重排。
5. 叠加影响力分数与多样性约束，输出 12–15 篇核心论文。
6. 每篇结果显示相关度、影响力、前沿性、证据完整度、桥接价值和入选理由。

分析结果与查询扩展结果缓存到 IndexedDB，同一论文和同一查询不重复消耗 API。

## 8. IC-Influence Rank

### 8.1 图结构

- 节点为本地论文，边由本地 PDF 的参考文献匹配产生。
- 标题和 DOI 与本地论文匹配成功后建立确定边；仅模糊匹配的边携带较低置信度。
- 可选从 OpenAlex 获取 DOI 对应的发表年份、总引用数和引用增速；失败时退化为本地图模式。

### 8.2 算法

- 使用主题个性化 PageRank：随机跳转向量由当前查询与论文的内容相关度决定。
- 时间先验采用温和指数衰减，并与引用增长速度组合，避免新论文因累计引用少而完全失去排名。
- 引用语义边权：奠基/采用方法高权重，扩展/验证较高，对比/反驳保留影响，背景罗列低权重，疑似作者自引降权。
- 最终核心分数：40% 内容相关度、30% 时间感知 PageRank、15% 引用增长与前沿性、10% 实验与证据完整度、5% 跨方向桥接价值。
- 使用 MMR 多样性重排，防止核心清单被同一技术分支占满。
- 输出角色标签：奠基论文、核心枢纽、前沿突破。

## 9. 用户界面

### 9.1 首次进入/新建论文库

- 顶部深海蓝流程条：连接 AI、导入论文、构建知识库、检索与图谱。
- 首屏同时展示 PDF 拖拽区和 DeepSeek 配置区。
- 显示本地隐私提示、浏览器存储容量、任务队列和连接状态。
- 主操作只有“测试连接”和“开始构建论文库”。

### 9.2 主工作台

- 左侧深海蓝导航：研究概览、本地论文库、智能检索、知识与影响力图谱、处理任务、设置。
- 顶部全局检索框。
- 图谱工作台采用三栏：左侧筛选、中央大画布、右侧论文评分与证据。
- 内容知识树与影响力图谱使用标签页切换。
- 核心论文清单提供排序、角色筛选和证据定位。

### 9.3 视觉系统

- 深海蓝：`#071A34`；核心蓝：`#176FE7`；冰川蓝画布：`#F3F7FC`；边框：`#DBE5F0`；正文：`#0B1D35`。
- 使用高对比度白色面板、精细 1px 边框、克制阴影和 8–16px 圆角。
- 中文标题使用宋体/衬线回退，界面正文使用 Segoe UI/Noto Sans SC。
- 避免营销式大面积渐变、霓虹和无意义装饰；视觉语义来自论文排版、精密仪器面板和引用网络。
- 所有关键操作具备 hover、focus-visible、loading、disabled 和 error 状态。
- 桌面端优先，宽度小于 1040px 时收起导航与论文详情；小于 720px 时改为纵向卡片，但保留上传和检索主流程。

## 10. 错误处理与恢复

- 无文本 PDF：标记“可能为扫描件”，保留文件但不进入 AI 队列。
- API 连接失败：区分认证失败、限流、网络失败、接口格式错误和模型不存在。
- JSON 结构错误：自动修复一次，仍失败则保留原始解析文本并允许重试。
- 浏览器存储不足：导入前估算容量，拒绝写入前给出清理建议。
- 页面刷新：从 IndexedDB 恢复任务；处理中任务回退到可重试的暂停状态。
- OpenAlex 不可用：显示“本地影响力模式”，不阻塞检索和图谱。
- 任一单篇论文失败不得中断整个批次。

## 11. 测试与验收

- 单元测试覆盖术语分词、结构化 JSON 提取、查询扩展回退、PageRank 收敛、时间先验、MMR 多样性、引用匹配和任务状态转换。
- 组件测试覆盖 API Key 保存策略、文件去重、队列暂停/继续、空库、失败状态和搜索结果解释。
- 集成测试使用内存 IndexedDB 和伪 DeepSeek 响应完成“上传文本型 PDF → 分析 → 检索 → 核心清单 → 图谱”的闭环。
- 构建产物必须能在 GitHub Pages 项目子路径运行，不包含真实 API Key，不依赖服务端路由。
- Lighthouse/静态检查目标：无阻塞错误，键盘可完成配置、上传、检索和结果查看；主要文字与控件满足 WCAG AA 对比度。

## 12. 首版成功标准

- 用户打开网页后无需安装软件即可创建独立本地论文库。
- 用户能输入自己的 DeepSeek 连接信息并完成连接测试。
- 批量导入文本型 PDF 后，处理状态可见、可暂停、可恢复。
- 论文能按集成电路知识域多标签归类并显示证据。
- 任意研究问题最多召回 50 篇，并输出 12–15 篇可解释的核心论文。
- 内容知识树和影响力图谱可搜索、缩放、筛选和查看论文详情。
- UI 达到已确认的深海蓝、冰川蓝、高密度科研工作台视觉标准。
